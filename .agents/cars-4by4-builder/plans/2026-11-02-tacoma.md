# Toyota Tacoma (3rd gen) — Implementation Plan

> For agentic workers: use superpowers:executing-plans. Steps use `- [ ]`.
> Spec: `.agents/cars-4by4-builder/specs/2026-11-02-interactive-builder-design.md` §1.

**Goal:** add the 2016–2023 Toyota Tacoma as a 7th vehicle in the truck group,
with its 3 presets, stock photo, gallery renders and Amazon links.

## Ground rules

- Branch `feat/cars-tacoma` from `main`. Never commit to `main`; merging and
  deploying need the user's OK.
- Gate: `npx turbo run type-check lint build --filter=cars-4by4-builder...`.
- Seed and test on the Neon branch `cars-credits` first:
  `DATABASE_NEONDB_SMARTEKAI="<cars-credits pooled url>" npm run db:seed -w cars-4by4-builder`.
- **Ask first:** production `db:seed`, `stock:generate`, `gallery:render`
  (Gemini credits + production storage), production `parts:links`.
- **Seed before links:** `db:seed` resets `parts.affiliate_url`. After any
  production seed, re-run `npm run parts:links -- ./scripts/parts-links.template.csv`
  (ask first) — otherwise the live Amazon buttons disappear.

## Steps

- [ ] **1. Vehicle.** Append to `seedVehicles`:

```ts
  { id: "tacoma-3g", name: "Toyota Tacoma", yearRange: "2016–2023", sortOrder: 7 },
```

- [ ] **2. Fitment.** In `parts.ts`, add `"tacoma-3g"` to `TRUCKS`. That puts it in
  `BOTH` and in every truck-only part. Update the header comment. Check that no
  part is wrong for a mid-size truck; all current truck parts exist for the
  3rd-gen Tacoma.
- [ ] **3. Presets.** In `presets.ts`, add `"tacoma-3g"` to `TRUCKS` and
  `"tacoma-3g": "tacoma"` to `VEHICLE_SLUGS`. The seed's fitment assertion must
  still pass.
- [ ] **4. Stock subject.** `SUBJECTS["tacoma-3g"] = "Toyota Tacoma (3rd generation, 2016–2023) double cab pickup truck"`.
- [ ] **5. Verify on the branch.** Seed; expect **7 vehicles, 24 parts, 21
  presets**. Click through: `/build` shows 7 vehicles; Tacoma lists the 14 truck
  parts; the 3 Tacoma presets open; an SUV-only part on the Tacoma is refused.
  Gate passes. Commit `feat(cars): add the 3rd-gen Toyota Tacoma`.
- [ ] **6. Amazon links (agent researches, user confirms).** For each per-vehicle
  truck part (Bilstein 5100 front, RC 2.5"/2" leveling, RC 6" lift, Fuel Vector
  17x9, Method 701 17x9, BAKFlip MX4) find the Amazon listing for the **2016–2023
  Tacoma 4WD double cab, 5 ft bed** and add rows `partId,https://www.amazon.com/dp/<ASIN>?tag=smartekaiover-20,tacoma-3g`
  with a one-line fit note comment above each (match the existing rows).
  Wheels: 6x139.7 — the GM ASINs may fit; confirm the listing names the Tacoma or
  6x5.5 with a compatible offset. Leave blank anything without a clear listing.
  Run `links:check` against the branch. Show the user the list of ASINs before
  production.
- [ ] **7. Production (ask before each).**
  1. `db:seed` on production.
  2. `parts:links` on production (restores the existing links + adds Tacoma).
  3. `npm run stock:generate -w cars-4by4-builder -- tacoma-3g` (1 Gemini call).
  4. `npm run gallery:render -w cars-4by4-builder` (3 Gemini calls; other presets
     are skipped as already rendered).
  5. Deploy only if code changed beyond seed data (it didn't: no deploy needed
     unless the user wants the sitemap refreshed — check whether the sitemap is
     built from the DB at request time).
- [ ] **8. Live check.** Gallery shows 21 cards and a Tacoma filter; a Tacoma
  build's Buy buttons lead to Amazon with `tag=smartekaiover-20`.
- [ ] **9. Record.** Log in `.agents/logs/`, current-work line in
  `.agents/cars-4by4-builder/plans/active.md`. Ask to merge.

## Done when

Tacoma is live with 3 rendered presets and its Amazon links; existing links are
intact; the gate passes; production steps happened only with the user's OK.
