# Live 3D preview — Implementation Plan

> For agentic workers: use superpowers:executing-plans. Steps use `- [ ]`.
> Spec: `.agents/cars-4by4-builder/specs/2026-11-02-interactive-builder-design.md` §3.
> Do this after the Tacoma and Help-me-choose plans.

**Goal:** a stylized, code-built 3D vehicle on the parts step that changes as
parts are ticked, reused on the report and public build pages. Browser-only;
zero added Worker CPU.

## Ground rules

- Branch `feat/cars-3d-preview` from `main`. Never commit to `main`; merging and
  deploying need the user's OK.
- Gate: `npx turbo run type-check lint build --filter=cars-4by4-builder...`.
- Add deps only with `npm install <pkg>@<exact version> -w cars-4by4-builder`
  (never edit the lockfile). `three`, `@react-three/fiber`, `@react-three/drei`,
  `@types/three` (dev). Pick versions that support React 19.3 and are ≥ 2 weeks
  old; record them in the log.
- The 3D code must **never run during SSR**: lazy import + mount check. No
  `three` import from any module the server bundle evaluates (check the built
  server chunk doesn't contain `three`).
- No imported 3D model files; everything is built from primitives.
- Validation: gate, dry-run bundle sizes, click-through on desktop and a
  375 px window, then a real phone after deploy.

## Files

- Create `apps/cars-4by4-builder/src/lib/visuals.ts` — `VEHICLE_SHAPES`, `PART_VISUALS`, `sceneSpec()` (pure, no three import).
- Create `apps/cars-4by4-builder/src/components/preview3d/Scene.tsx` — canvas, lights, camera, controls.
- Create `apps/cars-4by4-builder/src/components/preview3d/Vehicle.tsx` — body/cab/bed, wheels, suspension gap.
- Create `apps/cars-4by4-builder/src/components/preview3d/Accessories.tsx` — racks, tent, awning, bumper, winch, lights, snorkel, sliders, skid, tonneau.
- Create `apps/cars-4by4-builder/src/components/BuildPreview3D.tsx` — the lazy, client-only wrapper with the WebGL check and fallback.
- Modify `src/routes/build.tsx` (parts step), `src/routes/builds/$slug.tsx`, `src/routes/builds/$slug_.report.tsx`.

## Steps

### 1. `visuals.ts` (pure data, checkable without WebGL)

- [ ] `VEHICLE_SHAPES` for all 7 vehicle ids (`lc300`, `patrol-y62`,
  `wrangler-jl`, `f150`, `silverado-1500`, `sierra-1500`, `tacoma-3g`):
  `{ body: "pickup" | "suv", length, wheelbase, width, height, bedLength?, colour }`
  in metres, real-world-ish (F-150 ≈ 5.9 m long / 3.7 m wheelbase; Tacoma ≈
  5.4/3.2; LC300 ≈ 5.0/2.85; Wrangler 4-door ≈ 4.9/3.0). Distinct default
  colours per vehicle.
- [ ] `PART_VISUALS` for every part with a visible effect (table in spec §3).
  Parts not in the table are simply absent. Type:
  `{ kind: "lift"; inches: number } | { kind: "tyre"; inches: 33 | 35 } | { kind: "wheel"; style: "fuel" | "method" } | { kind: "lightbar" | "pods" | "roofRack" | "bedRack" | "tent" | "awning" | "bumper" | "stealthbar" | "winch" | "snorkel" | "sliders" | "skid" | "tonneau" }`.
- [ ] `sceneSpec(vehicleId, partIds)` → `{ shape, liftInches, tyreInches, wheel, accessories: Set<kind>, rackFor: "roof" | "bed" | null }`:
  max lift (stock 0), max tyre (stock 31), last-selected wheel style or stock,
  tent implies a rack (roof on SUV, bed on pickup) when none is selected,
  `tonneau` ignored on SUVs, `bedRack` on SUVs ignored (fitment already prevents it).
  Unknown vehicle → `null`.
- [ ] Spot-check with `npx tsx -e`: F-150 + [6" lift, Nitto 35, Rigid, tent] →
  lift 6, tyre 35, rack "bed"; LC300 + [] → stock; LC300 + [tent] → rack "roof".
- [ ] Commit `feat(cars): 3D scene description from parts`.

### 2. Install + client-only wrapper

- [ ] Install the deps (exact versions). Commit `build(cars): add three + react-three-fiber`.
- [ ] `BuildPreview3D({ vehicleId, partIds, className })`:
  - returns a fixed-height placeholder until mounted (`useEffect`), so SSR and the
    first client render match (no hydration warning);
  - WebGL check (`document.createElement("canvas").getContext("webgl2") ?? getContext("webgl")`);
    none → render `null`;
  - `const Scene = lazy(() => import("./preview3d/Scene"))` inside `<Suspense>`
    with the placeholder; an error boundary that renders `null` on failure.
- [ ] Commit `feat(cars): client-only 3D preview wrapper`.

### 3. Scene

- [ ] `Scene.tsx`: `<Canvas frameloop="demand" dpr={[1, 1.5]} camera={{ position: [6, 3, 6], fov: 35 }}>`,
  ambient + one directional light, a ground disc, a soft dark ellipse under the
  vehicle (no shadow maps). `OrbitControls` (from `@react-three/drei` by path):
  no pan, polar angle clamped above the ground, zoom clamped; `autoRotate` slow
  until the first pointer interaction. Invalidate on prop change.
- [ ] `Vehicle.tsx`: body from boxes with slightly bevelled edges
  (`RoundedBox` or extruded shape); pickup = cab + open bed with side walls; SUV =
  one cabin box; windows as darker inset panels; 4 wheels (tyre cylinder + rim
  disc; Fuel = spoked look via a few boxes, Method = flat disc with holes look);
  body height = base ride height + lift (1" ≈ 0.0254 m, exaggerate ×1.5 so mild
  lifts are visible); tyre radius from inches.
- [ ] `Accessories.tsx`: one small component per kind, positioned from the shape
  (e.g. roof rack on the roof, bed rack over the bed rising to cab height, tent as
  a flat box on the rack, awning as a rolled cylinder on the rack's side, light
  bar on the roof front edge, pods on the bumper, bumper/stealthbar at the front,
  winch on the bumper, snorkel up the right A-pillar, sliders under the doors,
  skid under the front, tonneau as a flat plate on the bed).
- [ ] Geometry memoized per `sceneSpec`; materials shared.
- [ ] Commit `feat(cars): stylized pickup and SUV with accessories`.

### 4. Placement

- [ ] Parts step (`build.tsx`): desktop — preview in a sticky column beside the
  parts grid; mobile — above the category tabs, ~260 px tall. Props:
  `vehicle.id`, `selected`.
- [ ] Report and public build page: the preview under the before/after slider,
  with that build's vehicle and part ids from the loader data.
- [ ] Commit `feat(cars): 3D preview on the builder, report and build pages`.

### 5. Verify

- [ ] Every vehicle renders and looks right at a glance (pickups have beds, the
  Tacoma is visibly smaller than the F-150, the Wrangler shorter than the LC300).
- [ ] Ticking each visual part changes the model; unticking reverts; parts
  without a visual change nothing; tent without a rack draws a rack.
- [ ] No hydration warnings in the console; the server build contains no `three`
  (`grep -rl "three" dist/server` or the dry-run output — whatever the build
  emits; record how you checked).
- [ ] WebGL disabled (Chrome `--disable-webgl` or devtools rendering setting) →
  no preview, page otherwise unchanged.
- [ ] Bundle: record the lazy chunk's gzipped size (target < 250 KB) and that the
  initial page JS didn't grow beyond a few KB.
- [ ] 375 px window: preview fits, page scrolls normally (rotating the model must
  not trap vertical scroll — use `touch-action: pan-y` on the canvas container and
  let OrbitControls handle only horizontal drags if needed).
- [ ] Gate; `npx wrangler deploy --dry-run --outdir /tmp/cars-dry`.

### 6. Ship (ask first)

- [ ] Ask to merge and deploy. After deploy: `/build?vehicle=f150&step=parts`
  and a report page 200; `wrangler tail` CPU for both recorded and unchanged vs
  before (the 3D is client-side); open on a real phone and confirm smooth rotation.
- [ ] Log + current-work line in `.agents/cars-4by4-builder/plans/active.md`.

## Done when

The 3D preview updates live on the parts step and shows on report/build pages
for all 7 vehicles; it never runs on the server; it degrades to nothing without
WebGL; bundle sizes recorded; gate passes; merged/deployed with the user's OK.

## Out of scope

Paint colour picker, open tent / awning animation, imported or licensed models,
AR, screenshots/export, per-trim body differences.
